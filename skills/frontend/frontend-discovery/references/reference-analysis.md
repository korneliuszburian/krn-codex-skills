# Reference analysis

## Observation boundary

Record provenance, access date, allowed use, and the exact surface observed.
Describe only what the evidence supports: content order, visible hierarchy,
layout relations, type treatment, imagery/crop, colour/surfaces, affordances,
motion, and differences across observed widths or states. Label a conclusion as
an inference when the reference does not prove it. A screenshot is neither a
licence to reuse assets nor an implementation specification.

## Inventory

For each meaningful region, name required content, likely semantic role,
primary/supporting relationship, visible action, and state or condition that
could change it. Capture the host seams that already constrain the result:
route, components, assets, localisation, values, styling, and evidence tools.

Use this evidence inventory per region: observed content and order; intended
semantic group; primary/supporting action; geometry/containment; type
scale/measure and rhythm; image subject/crop/alt intent; surface and
affordance; observed state/viewport; fact versus inference; and a screenshot
coordinate or other evidence pointer. Do not infer a hidden interaction or an
asset licence from pixels.

## Limit and falsifier

This is a dossier input, not source clearance, visual acceptance, accessibility
conformance, or a claim about hidden interaction. If an alleged fact cannot be
located in the observation or a permitted source, mark it unknown and obtain a
decision or research result rather than carrying it forward as intent.

## Provenance

Local mechanisms CV-01, CV-07, PS-01, and PS-11; HTML and WAI evaluation
guidance are the semantic and evidence boundary. This is original synthesis,
not a copied reference implementation.
