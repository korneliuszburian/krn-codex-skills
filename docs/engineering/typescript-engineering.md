# TypeScript Engineering

## Purpose

Sharpen TypeScript inference, public contracts, compiler configuration, module
resolution, and the proof boundary between static and runtime behavior.

## Invocation

Model-invocable or explicit as `$typescript-engineering`.

## Use and skip

Use beside a workflow that changes `.ts`, `.tsx`, `.d.ts`, `tsconfig`, or
module resolution. Skip ordinary JavaScript and workflow sequencing.

## Inputs

The owning workflow, changed TypeScript relationship, public or external
boundary, inference requirement, unsoundness claim, and repository-supported
typecheck.

## Output and completion

A readable type relationship that rejects invalid callers without erasing
useful inference, plus narrow static proof and runtime proof only where runtime
risk changed.

## Composition

Acts as a technical companion to `$implement`, `$diagnosing-bugs`,
`$code-review`, or `$codebase-design`; it never replaces their workflow.
