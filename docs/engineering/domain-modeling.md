# Domain Modeling

## Purpose

Replace competing live meanings with one canonical public concept, owner, and
migration boundary.

## Invocation

Model-invocable or explicit as `$domain-modeling`.

## Use and skip

Use for active naming conflicts, product concepts, or rare durable architecture
decisions. Skip passive reading, ordinary local names, and routine design.

## Inputs

The competing meanings, public seam, owner and consumers, observed
contradiction, trade-off, and change authority.

## Output and completion

A canonical term or model with invariants, excluded meanings, owned seams,
stale vocabulary, first migration slice, and falsifier. Completion requires an
executable decision or bounded handoff, not an unverified adoption claim.

## Composition

Uses `$source-to-decision` when an external source must justify the choice and
hands authorized production work to `$implement`.
