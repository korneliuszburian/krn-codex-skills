# Separate Bloom fidelity from frontend-method transfer

Bloom is the first real frontend-harness target, but it serves two different
questions. The fidelity benchmark starts from the exact admitted Complete CSS
0.1.3 starter and reconstructs Bloom against a frozen public design contract;
the transfer benchmark starts from a separately versioned
`boilerplate-rekurencja` static HTML/CSS/CUBE profile. Substituting the Rekurencja
profile into the fidelity task would confound starter differences with skill
effects, while treating the course starter as the production starter would make
the course the owner of Rekurencja project creation.

The task, reference freezes, experiment epochs, sealed reference, mutants, raw
runs, and experiment protocol belong to a new private `bloom-frontend-lab`
repository. KRN continues
to own only generic task/result, isolation, evaluator-axis, treatment, and
reporting contracts. `boilerplate-rekurencja` continues to own project creation,
canonical reusable core, and runtime profiles. Private course lessons remain an
external source store and are never candidate-visible or copied into KRN.

An admitted upstream completed source artifact or lab-owned private
reconstruction, later Figma rounds, the live Bloom site, and its pattern library
are acceptance references, not independent proof that the method generalizes.
BL-05 must establish the known-good's provenance; the live deployment is not
completed-source provenance. The candidate sees the admitted starter, a frozen export
of the admitted design round, public content/assets, and an original public
resolution log containing every requirement learned through design feedback.
The runner denies live Bloom, later-round, course, and evaluator access.

## Consequences

- `bop-2026`, `bloom-barista-www`, and old Sandcastle winners are not promotion
  consumers, golden answers, or candidate workspaces.
- Every third-party byte receives a rights/provenance class, private storage and
  retention rule, and publication boundary; a private repo does not itself grant
  redistribution authority.
- The first no-model gate is known-good green plus named mutants red. A model
  comparison is inadmissible until that gate passes.
- Bloom can establish in-domain source fidelity. A distinct transformed or
  unseen design task is required before claiming method transfer.
- WordPress/ACF is a later adapter track whose frontend and adapter results stay
  separate; it cannot rescue or invalidate the static fidelity result.
- Existing dirty experiment repositories are observed and harvested by contract
  only. Their generated runs, copied course text, hand-tuned winners, and prompt
  variants are quarantined rather than migrated.
