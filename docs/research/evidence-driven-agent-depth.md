# Evidence-driven agent depth

Status: `lab-test`. Consumer: the active Goal integrator, `sh-184` host-readback owner, and `sh-186` worker-transport owner before any new memory, compression, or investigation skill. Owner: maintainer. Verified: 2026-09-27.

This page decides whether Beads-style memory, `sqz`-style context compression, or an expensive opt-in investigation skill earns a KRN consumer. [Product architecture](product-architecture.md) owns the target truth planes and [ticket protocol](ticket-protocol.md) owns the queue and task links. This page is **not** another roadmap, memory register, implementation spec, or evidence that an agent works better.

## Decision boundary

Keep Sol as the sole writing integrator. The native control reads the live Goal, one selected Git-ref task snapshot, HEAD, and only source/lesson references missing for its next action. KRN's capsule is one outcome's restart cache; task comments belong to that task's history; gate-backed lessons and curated knowledge serve later outcomes. None can authenticate a user's revocation merely by being remembered. A read-only Luna or exceptional complex-question Astra reply is advice, never an independent approval or a second writer.

A premium workflow must beat that **unchanged native control** on an executed, decision-relevant task after counting source reading, model calls, parent verification, retries, compaction, host integration, and false blocks. Better-looking notes, shorter output, a model vote, or a green self-authored fixture do not qualify.

Beads' [`v1.0.4` prime](https://github.com/gastownhall/beads/blob/ce242a87967836a361a8f11f0674335173fdbb27/cmd/bd/prime.go#L81-L83) can also [pull stale Linear data](https://github.com/gastownhall/beads/blob/ce242a87967836a361a8f11f0674335173fdbb27/cmd/bd/prime.go#L310-L333) when credentials are configured. A session-start "read" is therefore not necessarily read-only; KRN must not copy it into a host hook without naming and authorizing the write.

Scientific constraints: [VibeMemBench v1](https://arxiv.org/html/2609.23570v1) uses executed coding tasks but selects targets with useful reference experience; all five frozen-transfer bootstrap intervals in Appendix J cross zero and eleven of twelve existing memory-system pairings do not beat matched memory-off. Bulky or generalized records can harm strong solvers. [Missing Complement v1](https://arxiv.org/html/2609.20050v1) improves **complete evidence-set recovery** in its captured states using three semantic calls, but evidence coverage and repair localization do not establish KRN task completion or zero online cost. [Impact Is Not Invalidation v1](https://arxiv.org/html/2609.25130v1) tests whether *a named claim*, not a whole diff, remains true; its execution oracle is a preserved test assertion, not proof that a user revoked an obligation. [Sleep-time Compute v1](https://arxiv.org/html/2504.13171v1) helps predictable questions at lower test-time budgets, but its coding case grades modified-file F1 rather than an executed repair and can lose to high-budget native inference. [MAST](https://arxiv.org/html/2503.13657) identifies coordination, repeated work and incorrect verification failures across multi-agent systems; prompted review alone is not a correctness oracle. None of these sources measures a KRN uplift.

## Observations against current KRN

- The public `krn task comment --body` already recorded a multiline `sh-182` checkpoint with author and fenced claim epoch; its Git-ref readback confirmed the result. Beads' `--stdin` removes shell quoting friction, **not** a missing memory database. A future `krn task comment --stdin` check must preserve newlines and refuse a stale epoch without writing.
- A read-only aggregate of this Pi session's last 250 tool-result records found 784,077 text bytes: 90 reads contributed 539,047 bytes and 129 bash results 218,533 bytes. Sixteen results were exact duplicates (four read and one bash duplicates); 87 exceeded 3 KB. This is raw session history, not the post-compaction model-visible projection or a matched cost study. Source reads dominate, while proof logs have already been redirected and summarized in this workflow. It does **not** justify squashing all tool output.
- The unpublished `sh-182` setup-stage candidate `0fe3f65f` passed its clean Node 22 gate (892/892), but a disposable counterexample showed that reapplying setup while both a selected Git-ref queue and contradictory `.krn/tickets` material exist currently exits 0. Both public queue names still read the selected ref, so this does **not** prove two live writers. It does show silent acceptance of competing material. A fix needs a legal selected+archived case and a negative selected+foreign-file case; no automatic deletion/import.
- The initial four first-wave, three specialist and one source-fidelity GPT-6 Luna questions plus one rare Astra adversarial question reached `message_end`/`agent_settled` at about $0.180 provider-reported cost (Astra $0.17005). Three later Luna discovery-specialist calls added about $0.0033 and a source-fidelity check about $0.0015. Sol's source reading, search/triage, verification, retries and user-facing context remain unmeasured; **these are research costs, not a product saving**. Raw packets/results stay temporary outside Git; this page keeps only source-checked mechanisms and limits.

## Decisions and experiments

1. **Adopt task-scoped provenance, not automatic memory promotion.** The selected task queue owns comments, claim epoch, dependencies, and close history; a fresh decision must still re-read the current Goal/task/HEAD. A comment may nominate a lesson, but the lesson owner requires a reusable rule, evidence, a reachable falsifier and retirement. The candidate `comment --stdin` belongs to the existing CLI; it fails if multiline readback changes text or if an absent/stale generation writes. No second register.
2. **Lab-test selected-source failure visibility at `sh-184`.** Reproduce a selected Git-ref source that is unavailable while plausible legacy Markdown remains, and a healthy empty selected source with legacy material. The former returns `unknown` and stops only the affected transition; the latter never resurrects legacy work. If native task/Goal reads already distinguish both cases and reach the right action, **reject a new warning, memory hint and decision-frame interface**. Codex hook trust and actual loaded behavior need genuine host readback.
3. **Defer compression plugins until an outcome-level opportunity is measured.** `sqz` and `pi-rtk-optimizer` compete at tool-result presentation; `context-mode` adds stronger routing and session-state ownership. First count decision-relevant, model-visible large/repeated outputs and prompt-cache billing on bounded KRN work. If material, compare unchanged Pi against the smallest opt-in transform through its existing `tool_result` seam, with command rewriting disabled and source/diff/trace/secret/unknown outputs passed through. Require exact recovery, negative mutants for dropped red tests and legal passes, equal model/window/tools, and end-to-end accepted task success. Count extra turns, re-reads, cache effects, privacy/storage, host/plugin cost and integration time. Stop and delete on a lost fact, false success, unavailable recovery, or no net benefit. A smaller shell summary or Pi's existing truncation is the control before a dependency.
4. **Lab-test a premium *explicit* depth brief, not a magic skill.** The literal word “sexy” collides with ordinary UI styling; a deliberate `/skill:<name>` or named prompt template is safer than automatic broad routing. First compare Sol composing the existing `$source-to-decision`, `$codebase-design` and `$delivery-loop` owners against the *same Sol* with a short opt-in brief. Both receive the same frozen question, source access, time/token budget, tools and authority. Require a hidden, independent source/implementation check and executed downstream acceptance; measure unsupported claims, misses, false blocks, retry, Luna/Astra/parent cost and wall. A bounded Luna question is earned by a named evidence gap; Astra only by a rare genuinely complex decision. A skill becomes installable only if repeated trials beat the direct owner baseline without extra false success. Stop or delete the draft if it merely lengthens the prompt, mandates subagents without need, or encourages a new authority. **No skill guarantees it will not err.**
5. **Lab-test checker-owned verdict precedence before any harness comparison.** Use the existing KRN harness owner and the OpenBench counterexample as a negative hypothesis: recovered 429 followed by a completed failing checker must remain a real failure, but a transport that never completed cannot be called a solve or wrong answer. Run both controls on KRN's own runner with pinned task/agent outputs, count excluded trials and lost cost, and stop without code if KRN already distinguishes them. An external benchmark's reported failure rate is not KRN evidence.

These are dispositions, not task publication. `sh-182` remains the current implementation item; `sh-183` owns alias retirement, `sh-184` host/Goal truth, `sh-185` real user authority, `sh-169` the authentic revoked-obligation/native-control pilot, and `sh-186` bounded transport. Any new tracked task needs its own queue authority and readback. A proven native failure may reopen one *conditional* mechanism in [product architecture](product-architecture.md); a green CI or vendor fixture cannot.

Reopen when an executed, matched native KRN decision fails and the named intervention clears its independent check at full cost; when `sh-184` exposes a silent host/source failure; or when a later source revision changes one of the pinned mechanisms. Otherwise keep the current planes and retire the unearned experiment rather than promoting a fashionable layer.
